# 仪器数据采集系统 - 需求共识文档

## 明确的需求描述

### 1. 多仪器并发采集
- 支持DLM5000示波器、WT3000和WT1804E功率分析仪的并发采集
- 提供同步和顺序两种采集模式
- 支持单次采集和持续采集（可配置采集间隔）
- 提供演示模式，无需真实仪器即可测试系统

### 2. 时间戳同步
- 生成统一的时间戳，确保多仪器采集数据的时序一致性
- 支持时间戳的精度控制（毫秒级）
- 提供时间戳校准机制，确保系统时间与仪器时间的同步

### 3. 标准化数据格式
- 定义统一的InstrumentData数据容器，包含仪器标识、类型、时间戳等基本信息
- 支持波形数据（WaveformChannel）和功率测量数据（PowerMeasurement）的标准化表示
- 提供原始数据的存储选项，便于后续分析

### 4. 数据分类存储
- 使用SQLite数据库存储数值统计数据（Max/Min/Avg/RMS/P2P等），不存储原始波形数据
- 提供数据索引和查询功能，便于快速访问历史数据

### 5. 可视化展示
- 提供实时数据可视化功能，支持波形图、趋势图等多种图表类型
- 支持数据筛选和时间范围选择
- 提供数据导出功能，支持CSV、Excel等格式

### 6. 自动报告生成
- 支持基于模板的自动报告生成
- 提供报告生成的触发机制（定时、手动、阈值触发）
- 支持Excel报告格式

## 验收标准

### 1. 功能验收
- 所有三种仪器均能正常连接和采集数据
- 并发采集模式下，同步模式时间戳完全一致，顺序模式时间戳误差不超过50ms
- 系统能够正确处理采集异常（如仪器连接中断）
- 数据存储和检索功能正常，无数据丢失
- 可视化展示能够正确显示采集数据
- 自动报告生成功能能够按预期工作

### 2. 性能验收
- 持续采集模式下，系统CPU使用率不超过50%
- 内存使用量不超过500MB
- 采集间隔设置为1秒时，系统能够稳定运行24小时以上
- 10万条记录的查询时间不超过1秒

### 3. 可靠性验收
- 系统能够自动重连断开的仪器连接
- 采集过程中出现异常时，系统能够优雅处理并记录日志
- 异常退出后数据不丢失（SQLite WAL模式保障）

## 技术约束

### 1. 硬件约束
- 仪器必须支持指定的通信协议（SCPI或自定义Socket）
- 网络连接稳定，延迟不超过100ms
- 存储设备有足够的空间存储采集数据

### 2. 软件约束
- Python 3.10+环境
- 依赖库：pyyaml, pyvisa, pyvisa-py（不锁定具体版本）
- 操作系统：Windows 10/11或Linux

### 3. 安全约束
- 不存储敏感信息（如密码、API密钥）
- 网络通信使用安全协议
- 数据存储加密（可选）

## 共识结论

1. **技术架构**：采用抽象接口层 + 适配器模式 + 观察者模式的架构设计，确保系统的可扩展性和可维护性。

2. **数据处理**：使用标准化的数据容器和分类存储策略，确保数据的一致性和高效性。

3. **性能优化**：采用线程池并发采集和时间戳同步机制，确保系统的性能和数据的时序一致性。

4. **功能扩展**：预留可视化和报告生成模块的接口，便于后续功能的扩展。

5. **开发计划**：按照6A工作流，先完成核心功能的开发和测试，再逐步扩展可视化和报告生成功能。
